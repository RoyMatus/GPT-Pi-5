# Развёртывание на Raspberry Pi

Эти файлы — примеры, не автоматический установщик. На Pi пока ничего не установлено.
Сначала проверить фактическую ОС, Python, браузер и графическую сессию.

1. Скопировать проект в выбранный каталог, создать venv и установить пакет:
   `python3 -m venv .venv`, `.venv/bin/python -m pip install .`.
2. Запустить вручную `.venv/bin/python -m gpt_pi`, открыть
   `http://127.0.0.1:8765` на самом Pi и проверить экран.
3. Для systemd создать непривилегированного пользователя `gptpi`, разместить
   приложение и venv в `/opt/gpt-pi`, проверить права чтения/исполнения.
   Адаптировать gpt-pi.service, затем установить в `/etc/systemd/system/`,
   выполнить `sudo systemctl daemon-reload` и `sudo systemctl enable --now gpt-pi`.
4. Проверить `systemctl status gpt-pi` и перезапуск после reboot.
5. Проверить название браузера: шаблон предполагает `chromium`.
   В среде с поддержкой XDG Autostart поместить адаптированный desktop-файл
   в `~/.config/autostart/` графического пользователя. Для другого compositor
   использовать его документированный способ старта. Графическая сессия должна
   запускаться при загрузке; это отдельно настраивается на целевой ОС.

Шаблон kiosk не ждёт готовности backend; до полноценного выпуска добавить retry/
экран загрузки и проверить порядок запуска на реальной ОС. Не отключать sandbox Chromium.
Голос, доступ к аудиоустройствам, секреты и writable storage требуют отдельного
пересмотра service hardening после реализации. Текущий demo ничего не сохраняет.

Откат примера: `sudo systemctl disable --now gpt-pi`, удалить только установленный
desktop-файл автозапуска. Не удалять пользовательские данные и не менять другие службы.

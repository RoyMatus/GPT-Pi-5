# Развёртывание на Raspberry Pi

## Личный прототип v0.3.2

Проверенная цель: Debian 13 ARM64, Python 3.13, labwc/Wayland, Chromium,
экран 720×1280 и установленная squeekboard. Адреса и пароли не входят в репозиторий.
Установщик не меняет ОС, сеть, SSH или другие службы и не требует sudo.

На компьютере разработчика:

```sh
npm ci
npm run build
python -m pip wheel . --no-deps -w dist
```

Передать wheel и `deploy/install-user.sh` на Pi по разрешённому SSH/SFTP.
Выполнить на Pi от графического пользователя:

```sh
sh install-user.sh /absolute/path/gpt_pi_5-0.3.2-py3-none-any.whl
systemctl --user is-active gpt-pi
curl --fail http://127.0.0.1:8765/health
```

Установщик создаёт отдельный venv в `~/.local/opt/gpt-pi/releases/DATE-TIME`,
устанавливает готовый wheel, переключает `current`, запускает пользовательскую
службу и проверяет `/health`. Предыдущий путь сохраняется для отката.
Node.js на Pi не нужен. Служба слушает только loopback, хранит данные регистрации
и сохранённый вход в `~/.local/share/gpt-pi`, не логирует URL/переписку.
Неизвестный браузер начинает без авторизации; постоянная cookie владельца восстанавливает вход.

Создаются `~/.config/systemd/user/gpt-pi.service`,
`~/.config/autostart/gpt-pi.desktop` и `~/.local/bin/gpt-pi-kiosk`.
Launcher ждёт сервер и запускает Chromium с отдельным постоянным профилем.
Окно запускается через `--kiosk --app=...`, включён Wayland text-input-v3.
Перед первым полноэкранным запуском на labwc выполнить настройку клавиатуры ниже.
Клавиатуру запускает графическая сессия ОС; launcher не запускает вторую копию.
При каждом запуске launcher включает автоматическое открытие через пользовательскую
настройку `org.gnome.desktop.a11y.applications screen-keyboard-enabled`.
После перезагрузки на проверенном Pi она оказалась выключена даже при работающей
клавиатуре; включение настройки восстановило автоматический показ без её перезапуска.
На проверенном устройстве используется системный `/etc/xdg/autostart/squeekboard.desktop`.
При переносе на другую ОС настроить один запуск squeekboard в графической сессии.
Sandbox Chromium не отключается.
Наличие графического входа при включении проверяется отдельно; установщик
не включает автологин ОС и не меняет менеджер входа.

Запуск окна в текущей Wayland-сессии:

```sh
~/.local/bin/gpt-pi-kiosk
```

С другого компьютера можно использовать SSH-туннель, указав свой HOST:

```sh
ssh -L 8765:127.0.0.1:8765 USER@HOST
```

Тогда открыть `http://127.0.0.1:8765` на этом компьютере. Порт должен совпадать
с callback сервера; если локальный порт занят, остановить собственный локальный
экземпляр либо согласованно изменить порт Pi и туннеля. Не слушать на `0.0.0.0`.

## Проверка и пределы

Проверить `/health`, экран, вход, сеть, отмену, выход, restart и загрузку устройства.
После `systemctl --user restart gpt-pi` вход сохраняется, история очищается.
Старую страницу приложение обновляет при следующей проверке статуса (до 10 секунд).
При переходе с прежнего приватного окна нужен вход один раз в постоянном профиле.
Для режима без сохранения задать службе `GPT_PI_REMEMBER_LOGIN=0`; тогда действует
выход через 30 минут бездействия. Перед переключением выйти из сохранённых сеансов:
сама настройка не удаляет существующие файлы доступа. Диск не зашифрован приложением.
Холодная загрузка/отключение питания, физический тач и качество аудио — отдельные
проверки, а не следствие успешных Python-тестов. Микрофон открывается только кнопкой «Говорить».

## Необязательный локальный голос

На Linux/Pi выполнить `python3 tools/install_voice.py` от пользователя приложения.
Для нестандартного data-dir передать `--data-dir /absolute/path`. Установщик создаёт
отдельный venv с Vosk 0.3.45 и Piper 1.8.0 и скачивает русские модели с проверкой
SHA-256, без sudo и изменения службы. Для заранее скачанных файлов есть `--assets-dir`.
Модели сохраняются при обновлении/откате приложения; wheel их не содержит.
Зависимости нужны для реального локального STT/TTS, а не для текстового режима.
Vosk/model-small-ru-0.22: Apache-2.0; Piper: GPL-3.0; голос Denis использует датасет CC0
(карточка модели сохраняется рядом с файлами). Лицензии моделей/движков отдельны от проекта.

После установки обновить страницу, разрешить микрофон по кнопке и выбрать
правильные вход/выход в аудиосистеме. Формат отправки на loopback: PCM/WAV mono
16 kHz, максимум 30 секунд. Озвучивание ограничено 2500 символами, рабочий процесс —
90 секундами. Сырые записи и ответы не сохраняются. Микрофон не включается при старте.
Проверка синтез → распознавание на Pi пройдена синтетической русской фразой;
живой capture/playback и эхо требуют отдельно подключённого рабочего аудиоустройства.

Источники: [Vosk](https://alphacephei.com/vosk/models),
[Piper](https://github.com/OHF-Voice/piper1-gpl),
[голос Denis](https://huggingface.co/rhasspy/piper-voices/blob/cf910fb59f1d79ab3b625a63993a108751c6c25d/ru/ru_RU/denis/medium/MODEL_CARD).

Проверка клавиатуры на Pi: выбрать пустое тестовое поле, дождаться появления
клавиатуры, нажать экранную букву, проверить символ в поле, затем снять фокус.
2026-11-10 на Chromium 154/labwc 0.20.2/squeekboard 1.43.1 этот сценарий
выполнен автоматизированным указателем на настоящем экране: появление, ввод `q`,
скрытие. До исправления воспроизведены скрытие под fullscreen и отсутствие
автоматического открытия; с единственной клавиатурой, включённой настройкой
и исправленным launcher сценарий прошёл. Это не проверка физического касания пальцем.
При диагностике использовать синтетическую страницу, не логировать ввод паролей.
Причина перекрытия описана в [labwc #2926](https://github.com/labwc/labwc/issues/2926).

Реальный OAuth завершается самим владельцем на официальном сайте OpenAI.
Наличие связи с auth.openai.com не гарантирует доступность аккаунта, региона,
подписки или модели. В журнал не копировать query string callback и токены.

## Откат

Остановить `systemctl --user stop gpt-pi`. Если существует previous-release,
проверить, что указанный каталог находится внутри `~/.local/opt/gpt-pi/releases/`.
Переключить symlink current на него и запустить службу. Если менялся unit,
в предыдущем установленном релизе сохранить/восстановить service-before-install,
затем выполнить `systemctl --user daemon-reload`.

Для отключения первой установки: `systemctl --user disable --now gpt-pi`,
переименовать только `~/.config/autostart/gpt-pi.desktop` в файл без расширения
`.desktop`. Пользовательские данные, каталоги релизов и другие службы не удалять.

Старый gpt-pi.service — пример отдельной системной установки в /opt.
gpt-pi-kiosk.desktop запускает установленный пользовательский launcher.
Текущий установщик создаёт собственные unit и desktop-файл.

## Панель v0.3

Launcher открывает `/?dashboard` с обзором; ассистент доступен на шестой вкладке.
Ключи/настройки ПК принадлежат проверенному облачному subject и остаются на backend.
События, город и избранное — RAM сеанса; фото — отдельное разрешение SFTP.
Нужен настроенный SSH-сервер источника и проверенные отдельные права для фото;
Windows без sshd не становится источником автоматически. Настройки сети/sshd ПК
и серверные ACL/chroot установщик устройства не меняет.


Профиль `~/.local/share/gpt-pi-browser` имеет права 0700 и использует
`--password-store=basic`: на устройстве с автоматическим входом заблокированный
GNOME Keyring останавливал загрузку HTTP до отправки первого запроса. Это
воспроизведено даже на минимальном локальном сервере; отдельный синтетический
профиль с файловым хранилищем сразу загрузил `/health`. Изменение ограничено
профилем панели, sandbox и сетевые проверки Chromium остаются включены.
Cookie этого профиля не защищены шифрованием keyring; пароль ОС не сохраняется.
Файловые права не защищают от root или кражи незашифрованного диска.
Не использовать этот профиль для хранения паролей других сайтов.

2026-11-11: v0.3.0 установлена через SSH на обнаруженный Pi; ключ хоста совпал
с ранее доверенным ключом. `/health` отвечает 200, пользовательская служба активна.
На установленном wheel ARM64/Python 3.13 прошёл 101 тест приложения; два теста
документации репозитория проверены только локально (общий локальный набор: 103).
На настоящем Chromium 154 проверены загрузка приложения, все шесть вкладок и

720×1218 при панели 720×1280: заголовок окна занимает оставшуюся высоту.
При последующей настройке v0.3.1 проверен действующий авторизованный сеанс
в текущем браузерном профиле; вход сохраняется при перезапуске окна.
Реальные чаты и облачные токены при проверке не извлекались.

Мониторинг реального ПК и слайд-шоу личной папки пока не приняты на реальном
источнике: на текущем Windows не установлен sshd, а отдельно разрешённый
SFTP-каталог с серверными ограничениями не настроен. Pi не выдаётся за внешний ПК.
Необходимость входа владельца и настройки источника показана в интерфейсе.


## Полный экран и клавиатура v0.3.1

На labwc fullscreen находится выше слоя top, используемого squeekboard.
Передать install-osk-overlay.sh и osk-overlay.c на Pi в один каталог.
`deploy/install-osk-overlay.sh` собирает небольшой GTK3-модуль и создаёт
пользовательский override автозапуска единственной клавиатуры. Системный бинарник
squeekboard не заменяется. Нужны существующие cc/pkg-config и libglib2.0-dev
(на Debian установить этот пакет отдельно с правами администратора).

```sh
sh deploy/install-osk-overlay.sh
```

Модуль загружается только wrapper-ом squeekboard, проверяет процесс и тип
PhoshLayerSurface/namespace osk, меняет лишь слой этой поверхности на overlay.
Он сообщает только visible/height/монотонное время в файле 0600 внутри
`$XDG_RUNTIME_DIR/gpt-pi-osk` (0700, tmpfs). Текст, нажатия и аккаунты не читаются.
Backend отвергает чужой, небезопасный, чрезмерный или устаревший файл; `/api/keyboard`
возвращает только visible/height в физических пикселях. UI учитывает devicePixelRatio
(включая масштаб браузера). Во время ввода оболочка резервирует реальную
высоту клавиатуры; после скрытия возвращает весь экран. Перестроение не должно
перемещать нажатую кнопку между pointer-down и click.

Проверено с squeekboard 1.43.1 / labwc 0.20.2 / Chromium 154: viewport равен
разрешению экрана 720×1280, клавиатура видна поверх fullscreen, синтетическая
экранная `q` попадает в поле и клавиатура скрывается после blur. Физическое касание
пальцем это не подтверждает. Вход владельца в приложении подтверждён без извлечения
cookie или облачных токенов. Модуль не изменяет lockscreen или его правила.
Для отката восстановить сохранённый пользовательский squeekboard.desktop из
`~/.local/lib/gpt-pi-osk/squeekboard.desktop.before`, если он есть; иначе убрать
только созданный override. Затем перезапустить графическую сессию и вернуть
предыдущий launcher. Старые пользовательские данные/профиль браузера не удалять.

Основания: [порядок слоёв labwc](https://github.com/labwc/labwc/issues/2926),
[исходники установленного squeekboard](https://archive.raspberrypi.com/debian/pool/main/s/squeekboard/squeekboard_1.43.1-1+rpt1.dsc),
[GObject emission hooks](https://docs.gtk.org/gobject/func.signal_add_emission_hook.html).

## SSH-телеметрия с Windows

`setup-windows-telemetry.ps1` — отдельная явно запускаемая администратором настройка,
не часть модели или автоматических действий приложения. Предварительный просмотр
по умолчанию; `-Apply` устанавливает официальный Windows OpenSSH Server через
Windows Capability, создаёт стандартную локальную учётную запись gptpi-monitor
с неизвестным случайным паролем и разрешает только ключ с Pi. Приватный ключ
телеметрии остаётся на backend Pi. Параметры хоста/адреса передаются при запуске,
в Git они не сохраняются.

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File deploy/setup-windows-telemetry.ps1 `
  -PublicKeyPath C:/private/telemetry.pub -HostKeyPath C:/private/host_ed25519 `
  -DeviceAddress DEVICE_IPV4 -ListenAddress PC_IPV4
# После просмотра повторить с -Apply в повышенной PowerShell.
```

RemoteSigned задаётся только процессу, общая политика исполнения не меняется.
Если уже есть чужая SSH-служба/одноимённый аккаунт, установщик останавливается.
Конфигурация/коллектор защищены ACL SYSTEM/Administrators; аккаунт имеет только
чтение нужных файлов. ForcedCommand выполняет фиксированный ограниченный по времени
коллектор, даже если клиент просит другую команду. Парольный вход, PTY, forwarding
и SFTP этой учётной записи не разрешаются. Firewall принимает только адрес Pi
на выбранном локальном адресе; автоматически созданное широкое правило отключается.
При ошибке служба останавливается, конфигурация до установки сохранена для отката.
Фото требуют отдельной настройки SFTP/серверных ACL и этим установщиком не разрешаются.

Установка службы требует штатного UAC Windows. Успешный preview или создание
профиля в приложении не означает установленный сервер: отдельно проверить службу,
ключ сервера и получение реальных метрик с Pi, включая запрет произвольной команды.
Документация: [Microsoft OpenSSH](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse),
[конфигурация Windows OpenSSH](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-server-configuration).


Сетевой WMI-запрос Win32_PerfFormattedData может превышать timeout и раньше
срывал также получение CPU/RAM/диска. Windows-коллектор использует встроенный
NetworkInterface.GetIPStatistics: сумма байтов доступных интерфейсов без loopback,
GetTickCount64 для монотонного интервала и расчёт бит/с на backend между реальными
замерами. Первый замер/сброс счётчиков не выдаётся за нулевой трафик. Недоступный
сетевой интерфейс не срывает остальные показатели. Дополнительные группы доступа
к performance counters не требуются. Failed job сохраняет причину ошибки;
восьмисекундный deadline и cleanup остаются, stderr не отдаётся в UI.

Источники: [Microsoft NetworkInterface](https://learn.microsoft.com/en-us/dotnet/api/system.net.networkinformation.networkinterface.getipstatistics?view=net-10.0),
[GetTickCount64](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-gettickcount64).

Все Windows CIM-запросы исключены из конечного коллектора: в SSH воспроизведён
также timeout Win32_Processor. CPU читается через GetSystemTimes за интервал 250 мс,
физическая память — GlobalMemoryStatusEx, диск — DriveInfo, сеть — IP-interface
byte counters. CPU frequency/температуры/GPU не выдумываются. На >64 logical CPU
нагрузка CPU не поддерживается из-за processor-group семантики GetSystemTimes.
[Microsoft CPU times](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getsystemtimes),
[Microsoft memory](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex).

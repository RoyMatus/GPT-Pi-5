# Архитектура

Статус: целевая архитектура ниже остаётся планом. Реализован личный текстовый
прототип v0.2, описанный в следующем разделе.

## Реализовано в v0.2

Fluent UI React v9 собирается esbuild в статические assets, включаемые в wheel.
Starlette/Uvicorn слушает только 127.0.0.1. Runtime владеет случайными серверными
сеансами, состоянием OAuth, connection, каталогом моделей, чатами и задачами
streaming. HttpOnly/SameSite cookie содержит только случайный идентификатор;
Origin+CSRF защищают изменения, Host-проверка ограничивает DNS rebinding.
Cross-site обращения блокируются, кроме OAuth callback и GET корневого HTML
как top-level document: браузер сохраняет cross-site при возврате из OpenAI.
HTML не содержит данных сеанса; cross-site API и встраивание страницы запрещены.

Authlib реализует OAuth/PKCE, PyJWT/cryptography — проверку RS256, issuer,
audience, exp, iat, nonce и azp. Облачный transport подменяется в тестах.
Каждый чат доступен только через текущий серверный Session; клиентские owner ID
не принимаются. Выход отменяет задачи и очищает RAM. Перед каждой
порцией потока повторно проверяется живость сеанса. Неуспешный/оборванный ответ
помечается незавершённым. Перезапуск восстанавливает только сохранённый вход.

В data-dir сохраняются host ID и client ID с хешем subject. Отдельное backend-хранилище
credentials содержит имя, subject и access/refresh/ID tokens, индексированные хешем
случайного секрета cookie. Восстановление требует cookie и совпадения регистрации;
анонимный браузер не получает аккаунт. История и аудио остаются в RAM, пароль не принимается.
Каталог 0700, атомарно заменяемые файлы 0600 на Linux, блокировка второго процесса,
refresh сериализован. Cookie HttpOnly/SameSite живёт до 400 дней и продлевается
при чтении статуса; это не меняет сроков облачных токенов. Временная ошибка refresh
оставляет запись, терминальная удаляет её. Logout удаляет запись до завершения сеанса;
позднее сохранение не может восстановить удалённый вход. Опция remember_login=0
возвращает RAM-only режим с idle expiry 30 минут. Шифрование данных на диске не реализовано.
Предполагается доверенный пользователь ОС; защиты от root, чтения RAM/диска,
захвата браузерного сеанса и подмены приложения нет. Это не локальная
многопользовательская аутентификация. Профили доменной модели пока отделены от UI.

Вход на сайте OpenAI и вход в приложение не одно и то же: logout приложения
не удаляет cookies OpenAI. Kiosk использует отдельный постоянный профиль Chromium.
Режим API-key и tools в прототипе отсутствуют.

Локальный голос: Chromium AudioWorklet записывает только после явного нажатия,
до 30 секунд. PCM/WAV mono 16 kHz передаётся на loopback с Origin/CSRF-проверками.
Vosk преобразует его в редактируемый текст; только текст отправляется в ChatGPT.
Piper синтезирует WAV для озвучивания ответа до 2500 символов. Русские модели и
отдельный venv устанавливаются в data-dir/voice; они не включены в wheel.
Обработка выполняется отдельным процессом с ограничением времени, одним на устройство;
отмена/выход убивают процесс, проверка действующего Session исключает поздний результат.
Аудио и текст идут через stdin/stdout и RAM, stderr движков отключён.
Браузер отменяет микрофон/звук при выходе, смене чата и скрытии страницы; позднее
разрешение микрофона не запускает запись после отмены. Озвучивание слышно окружающим.

Local backend (Python)

## Решение ADR-001: локальное приложение и отдельные адаптеры

Python упрощает интеграцию с Linux и оборудованием, web UI подходит для тача.
В v0.2 HTTP-маршруты реализованы на Starlette/Uvicorn; Authlib обслуживает OAuth/PKCE,
PyJWT/cryptography проверяют ID token. При расширении использовать эти компоненты
и сохранять проверку действующего сеанса; не развивать собственную криптографию.
Альтернатива: Qt. Пересмотреть выбор, если браузер окажется тяжёлым на реальном экране.

## Решение ADR-002: три идентичности

CloudConnection: облачный principal, способ оплаты и секреты владельца.
LocalProfile: отдельный человек, его аутентификация и разрешения.
OS user: служебный пользователь Linux, не личность собеседника.
Не использовать cloud account ID как владельца всех локальных разговоров.

## Хранилище и приватность (проект)

Первый кандидат — SQLite для метаданных и отдельные каталоги артефактов.
Все сущности, включая embeddings, exports и tool credentials, привязаны к profile ID.
Сервис получает профиль только из проверенной сессии, не из тела запроса.
Запросы всегда фильтруются по владельцу; неизвестный и чужой ID дают одинаковый ответ.
Шифрование данных и управление ключами проектируются до сохранения личных разговоров.
Пароли хешируются современной проверенной библиотекой; нужны ограничение попыток
и безопасное восстановление. Короткий PIN без защиты от перебора недостаточен.

Текущий ConversationStore — только in-memory доменная иллюстрация проверки владения.
Он доверяет переданному principal и НЕ является системой аутентификации.
Он не подключён к HTTP. Lock аннулирует локальную сессию; будущие асинхронные
обработчики должны повторно проверять сессию перед доставкой каждого ответа.

## Голос и состояние

В текущем прототипе гостевая проверка звука записывает пять секунд только в RAM
браузера и воспроизводит запись или синтетический сигнал. Закрытие/скрытие окна
останавливает проверку и удаляет запись. GET /api/audio/devices читает PipeWire
через ограниченный по времени pw-dump; ответ содержит только признаки наличия
микрофона/динамика, без имён и ID. Dummy Output исключён, недоступность инструмента
означает неизвестное состояние. Результат кэшируется на две секунды; действуют
общие Host/Fetch-Metadata ограничения. Перечисление камер браузером не используется.

idle → listening → thinking → speaking → idle; ошибки → visible error.
При lock: cancel generation, stop capture/playback, close provider session,
clear UI/context/buffers. Запись по нажатию по умолчанию; wake word — позже.
Начать с измерения USB-аудио, эха и задержки; не выбирать STT/TTS без проверки устройства.

## Автозапуск

Backend запускается systemd от непривилегированного пользователя.
Kiosk UI — после старта графической сессии. Он обращается только к loopback.
Для будущего многопользовательского режима автологин ОС не должен открывать профиль.
В личном прототипе сохранённая cookie явно разрешает повторный вход владельца.
Обновления должны допускать откат; изменения схемы — с проверкой резервной копии.

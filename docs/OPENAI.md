# OpenAI: факты, ограничения и решения

Проверка официальной документации: 2026-11-10.

## Реализация личного прототипа v0.2

Используется документированный поток для локальных личных проектов:
dynamic_agent_client для первоначальной регистрации, стабильный ext_agent_host_id,
loopback callback, state/nonce/PKCE, выданный client_id для code exchange.
Authlib и PyJWT/cryptography проверяют OAuth и подпись/claims. Только выданный
scope chatgpt.tokens.use.direct разрешает inference. Каталог /v1/models читается
как models с visibility=list; slug передаётся в /v1/responses. Каждый запрос
store=false, stream=true; успех — только response.completed.

Секреты только в памяти backend. Клиентская часть получает безопасный статус,
модели и текст. Refresh сериализован, выход отменяет задачи и пытается отозвать
renewable session через revocation_endpoint официального discovery. Неподтверждённый
отзыв отображается пользователю. Нет обхода через cookies, backend-api или API-key.

Контракт покрыт автономными тестами. 2026-11-10 на Pi подтверждены реальный вход
владельца, получение каталога моделей и завершённый ответ GPT-6.1-Sol через
разрешение на использование плана ChatGPT. Отдельный API-ключ не применялся.
Первый возврат из OpenAI выявил локальный 403: Fetch Metadata сохраняет cross-site
на цепочке перенаправлений. Исправление допускает GET главной страницы только
как top-level document; cross-site API, iframe, POST и неверный Host остаются закрыты.
Это проверка конкретного аккаунта и текущего соединения; доступность для иных
аккаунтов/регионов и все возможности подписки этим не подтверждаются.

Согласно текущему Cookbook, локальные личные проекты допускаются отдельно от OSS.
Выбор лицензии остаётся открытым, но не объявляется техническим блокером личного
локального прототипа. Платные/удалённо размещённые приложения требуют отдельного доступа.

Для подходящих Pro/Business документированы включённые API-кредиты, в том числе
для голоса. Они требуют активации в конкретном аккаунте и не реализованы как
способ оплаты в этом прототипе. Наличие Pro само по себе не подтверждает активацию.

## Подтверждённые факты

- Sign in with ChatGPT предусматривает вход и отдельное разрешение на использование
  плана для допустимых запросов. Документация описывает open-source flow и
  ограниченный доступ для некоторых других клиентов. Это не выдача всех функций ChatGPT.
- Identity scopes сами по себе не дают доступа к беседам ChatGPT или API.
- В preview использования плана есть ограничения: в частности, отсутствуют
  аудиовход, transcription и ряд hosted tools, включая image generation.
- Realtime WebRTC имеет отдельный документированный путь с backend-аутентификацией
  API-ключом. Нельзя считать, что OAuth-токен плана поддерживает этот же путь.
- Облачные токены должны оставаться в защищённом локальном/backend-хранилище.

## Вывод для проекта

Вход через ChatGPT оставляем в требованиях и проектируем отдельным адаптером.
Для голоса исследуем API Realtime либо локальные STT/TTS с текстовой моделью.
Переход на API с оплатой по использованию должен быть явным выбором владельца.
Не делать скрытый fallback при исчерпании подписки.
Матрица capabilities зависит от подключения, модели и проверенных разрешений.

## Пока не установлено

- Доступность регистрации/плана для других аккаунтов и вариантов подключения.
- Допустима ли схема «несколько людей используют одну персональную подписку».
  Технические локальные профили не доказывают такое разрешение.
- Региональная доступность по месту эксплуатации и ограничения конкретного аккаунта.
- Точный набор моделей, квоты, стоимость и права на каждый инструмент.
- Подходит ли проект под OSS-flow: публичный репозиторий без OSS-лицензии
  сам по себе не подтверждает соответствие.

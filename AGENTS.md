Работать только в этом проекте и явно разрешённых ресурсах. Не открывать и не
изменять соседние проекты. Перед правкой проверить состояние Git и сохранить

Сначала прочитать README.md и docs/AI_CONTEXT.md; остальные документы — по задаче:

## Разработка и доказательства

- Python 3.11+, src/gpt_pi; без новых зависимостей без конкретной необходимости.
- Разделять факты, выводы и гипотезы. Не называть заглушки работающими функциями.
- Не менять несвязанные части и не редактировать сгенерированные файлы.
- Проверять новые/сомнительные API по актуальной официальной документации;
  использовать подключённый Context7, если уместен, и не повторять уже достаточное исследование.
- Для проверяемого нового поведения/воспроизводимой ошибки сначала получить
  тест, обнаруживающий отсутствие поведения/ошибку. Исключения и альтернативы — TESTING.md.
- Выбирать проверки по риску. Правка текста не требует запуска приложения.
  Не повторять успешные проверки неизменённого кода без причины.
- GitHub Actions разрешены. Windows/Linux CI не заменяет проверку Linux/ARM64,
  микрофона, динамика, экрана и автозапуска на реальном устройстве.
- Платные API не запускать в тестах/CI. Не менять ОС Pi и автозагрузку без задачи на развёртывание.
- Обновлять обе версии README при изменении описанных команд/возможностей;
  docs/AI_CONTEXT.md и roadmap — при изменении фактического состояния.

## Приватность устройства

Секреты, настоящие чаты, аудио и личные данные не попадают в Git, логи и issues.
Облачные токены остаются на backend. Локальный профиль, облачный аккаунт и
пользователь ОС — разные идентичности; подписка не гарантирует все функции API.
Владелец каждого диалога/файла/памяти проверяется сервером из действующей сессии,
а не из переданного клиентом ID. При блокировке отменять запросы, останавливать
запись/звук и закрывать поток; поздние ответы не должны попасть другому человеку.
Микрофон включается явно с индикацией. Модель не получает произвольный shell;
внешние/опасные действия требуют подтверждения пользователя устройства.
Не обещать защиту от root/кражи диска без соответствующей модели шифрования.

## Роли и совместная работа

Навыки: .agents/skills; роли: .codex/agents. По умолчанию выполнять простую задачу
одним агентом. Делегировать только при разрешении пользователя/действующих правил
и реальной пользе: конкретный результат, владелец файлов, уже известные факты
и выполненные проверки. Один владелец координирует устройство и тяжёлые проверки.
Родитель отвечает за интеграцию и публикацию. Профили не расширяют права сессии.
